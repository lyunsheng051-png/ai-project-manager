# AI Project Manager · 项目工作台

面向 AI 辅助开发的本地项目工作台。导入仓库、核对服务配置、启动项目、使用终端、检查并提交代码。

第一版以 Windows 本机开发为目标，采用 Electron、Vue 3、TypeScript。当前提供源码开发版，尚未制作安装包，也没有 AI 模型调用和后台 AI 服务。

![紧凑的 Git 工作区，使用临时示例项目进行真实桌面验证](docs/images/workspace.png)

## 已实现功能

- 导入本地项目、克隆 HTTPS / SSH 仓库、最近项目、搜索和收藏。
- 规则扫描 Node 项目、FastAPI 入口及 Java 描述文件，支持一个仓库多个服务，重复扫描保留自定义配置。
- 添加和编辑服务目录、命令、环境变量、就绪地址及启动依赖；启动、停止、重启和按依赖组合启动。
- 有界服务日志、日志筛选、复制、自动滚动；基于 PTY 的多标签终端。输出面板顶部分隔线支持上下拖动调整高度，双击恢复默认。
- Git 状态、文本差异、文件级暂存/取消暂存、提交、创建与切换分支、Fetch、仅快进拉取、推送、合并和中止合并。
- 目录按需读取、文本预览、在系统文件管理器中定位文件。
- Git 变更文件逐项完整列出，支持滚轮滚动、单独选择和全选；其他列表默认每页 10 条，可选择 20 / 50 条。
- 项目名、分支与路径合并在紧凑顶栏中；Git 文件列表和差异区域独立滚动，提交输入区保持可见，日志和终端仍支持拖动调高。
- 应用进程工作集和 CPU 统计，明确区分应用开销与项目服务开销。

## 启动

需要本机已配置 Node.js、npm 和 Git。项目运行命令复用本机开发环境；Python 项目优先使用 uv。首次运行需要联网下载 Electron 运行时。

```powershell
npm.cmd ci
npm.cmd run dev:desktop
```

也可以双击 `start.cmd`。请先完成依赖安装。

运行后自动弹出独立的 Electron 客户端窗口，无需打开浏览器。开发版内部启动本机界面服务并自动选择空闲端口；退出客户端后，该服务一同关闭。

| 命令 | 用途 |
| --- | --- |
| `npm.cmd run dev:desktop` | 打开可正常使用的桌面客户端 |
| `npm.cmd run desktop` / `npm.cmd run dev` | 桌面启动的兼容别名 |
| `npm.cmd run dev:web` | 只启动浏览器界面预览，不具备桌面文件、Git 和终端能力 |
| `npm.cmd run test:desktop` | 自动化验证，使用隐藏窗口及临时项目，完成后退出 |

PowerShell 中使用 `npm.cmd` 可避免 `npm.ps1` 被脚本执行策略拦截；允许脚本执行的环境也可以直接使用 `npm`。

桌面开发模式仅转换 Electron 主进程代码，不执行前端生产构建。修改 Vue 文件会热更新；修改 `electron/` 或 `shared/` 后请退出并重新执行启动命令。

首次打开后：

1. 导入本地项目或克隆仓库。
2. 在“运行服务”中核对扫描得到的工作目录和命令，必要时新增或编辑配置。
3. 在终端中安装目标项目所需依赖。
4. 单独或组合启动；可以填写本机 HTTP 地址来确认服务就绪。
5. 在“Git 变更”中检查差异、选择文件暂存、填写说明并提交。

扫描不会执行项目脚本，也不会自动安装依赖。Java 聚合模块及无法确定的 Python 入口需要手工补充启动命令。自定义命令会在用户选择的项目目录中，由本机 shell 执行。

Windows 服务命令和交互终端默认使用 `cmd.exe`，支持 `npm run dev`、`uv run ...` 等常见命令，不受 PowerShell 脚本执行策略影响。需要 PowerShell 时可在终端输入 `powershell -NoProfile` 手工进入。

## 验证

```powershell
npm run typecheck
npm test
npm run test:desktop
npm run test:desktop:launch
```

- `typecheck` 同时检查 Vue 渲染端、共享类型及桌面主进程，不运行前端 build。
- `test` 在系统临时目录建立独立仓库，验证扫描、路径边界、配置存储及真实 Git 行为。
- `test:desktop` 通过 Playwright 启动真实 Electron，使用临时项目和应用数据目录，验证界面操作、PTY、HTTP 就绪、进程清理和 Git 操作；截图保存在 `.runtime/screenshots/`。
- `test:desktop:launch` 验证正常启动入口，会短暂显示并自动关闭一个临时客户端窗口；检查原生窗口可见、测试标志不影响正常启动、网页预览端口被占用时仍可启动及关闭后的清理。
- 自动化不对用户真实仓库执行提交、合并或推送。临时测试目录保留以便失败时排查。

验证场景和结果见 [验证记录](docs/verification.md)，实现边界见 [架构说明](docs/architecture.md)。

## 目录结构

```text
electron/
  core/                 路径约束、串行任务等基础能力
  repositories/         本地项目配置存储
  services/             项目扫描、Git、文件、PTY和服务进程
  main.ts               桌面生命周期与IPC接口
  preload.cjs           隔离的桌面桥接
shared/                 IPC数据契约
src/
  api/                  桌面接口调用
  components/           项目、服务、Git、文件、终端及通用组件
  composables/          工作空间状态与分页逻辑
  config/               展示映射
  layouts/              应用框架
  router/               页面路由
  styles/               设计变量、布局及组件样式
  types/                前端共享类型入口
  views/                工作台、设置页面
scripts/                启动与桌面验证脚本
tests/                  核心行为回归测试
docs/                   架构、限制与开发记录
```

## 数据与行为边界

- 项目记录保存在 Electron `userData` 下的 `projects.json`，不会写入目标仓库。环境变量目前以明文保存在该本机文件中。
- “移除项目记录”会停止受管进程并移除应用记录，不删除磁盘项目。
- 进程日志和终端历史有缓冲上限，关闭应用不会保存完整历史；关闭有受管进程的窗口时需要选择是否停止并退出。
- 停止服务仅针对本工具创建的进程树，不会根据端口号结束未知进程。
- Git 复用系统凭据。当前版本不内置登录管理、图形冲突编辑器、rebase或强制推送；合并冲突需要通过终端/编辑器处理后暂存提交，或中止合并。
- 未绑定上游的新分支首次推送使用 `origin`；已绑定的分支使用原有 Git 推送配置。
- 项目移除、服务停止等状态会以实际执行结果为准；应用崩溃或被强制结束后的进程接管不在第一版范围内。

## 资源占用说明

界面展示的是 Electron 各应用进程的工作集合计，可能重复计算共享页，不包含用户启动的服务。开发服务器和生产发行版也不是同一测试条件。当前未承诺固定内存指标；后续将基于明确场景记录冷启动、空闲、日志输出、多个终端及项目切换的基线。

## 后续方向

项目工作台是一个开源的本地开发桌面工具，适合同时维护多个仓库、前后端服务和日常 Git 操作的开发者。导入已有项目，核对启动命令，就能在一个窗口里管理服务、查看日志、打开终端、编辑文件和提交代码。

界面采用玻璃质感设计，提供浅色与深色主题。基础功能直接使用本机开发环境和系统 Git，无需配置模型 API Key。项目名称中的 AI 表示后续扩展方向，当前版本尚未接入 AI 模型。

![浅色主题：项目卡片、多服务管理与实时日志](docs/images/workspace.png)

> 当前提供源码运行方式，优先支持 Windows，尚未提供发行安装包。本文截图取自当前源码界面，使用独立示例仓库；示例项目和日志仅用于展示。

## 为什么做这个工具

一个项目往往同时有 Web、API 和后台任务。日常开发需要反复切换目录、终端和 Git 工具，重新找到启动命令，再确认哪些服务仍在运行。

项目工作台希望把这些重复操作收在一个地方：记住每个仓库的运行配置，让项目切换、服务管理和代码提交更顺手。它提供轻量编辑和 Git 合并能力，适合与常用 IDE 配合使用。

## 界面与功能

| 模块 | 可以做什么 |
| --- | --- |
| 项目空间 | 导入本地目录、克隆 HTTPS / SSH 仓库，搜索、收藏和切换项目，收起侧边栏 |
| 运行服务 | 识别常见项目入口，配置多个服务，按依赖组合启动，停止、重启并查看状态 |
| 文件浏览 | 树形目录、多标签代码编辑、新建、复制、拖入、批量选择、移入回收站和图片预览 |
| Git 工作区 | 查看差异、暂存、提交、分支切换、获取、拉取、合并远端和推送 |
| 冲突合并 | 独立三栏弹窗、冲突点导航、左右采用或拒绝、可编辑结果与撤销操作 |
| 日志与终端 | 日志筛选、复制与跟随输出，多标签 PTY 终端，可拖动调整面板高度 |
| 外观 | 浅色 / 深色切换、玻璃卡片与背景、具有操作含义的按钮颜色 |

### 多服务，在一个地方启动

- 扫描 Node.js 项目、FastAPI 入口和 Java 项目描述文件；复杂项目可手工添加配置。
- 每个服务独立配置工作目录、命令、环境变量、HTTP 就绪地址和启动依赖。
- 运行服务完整列出，可单独启动，也可按依赖顺序组合启动。
- 查看实时日志与进程状态；停止操作针对工作台创建的进程树。
- 重复扫描保留已有自定义配置。扫描本身不会安装依赖或执行项目脚本。

### 树形文件浏览与代码编辑

![文件浏览：目录树、多个文件标签与代码高亮](docs/images/file-browser.png)

- 目录按需展开，支持键盘导航；文件树与编辑区之间可左右拖动调整宽度。
- 点击文件打开独立标签，支持语法高亮、行号、括号匹配和缩进。
- 直接编辑，按 `Ctrl+S` 才写入磁盘；切换标签保留草稿、光标和编辑器撤销记录。
- 工具栏或右键菜单新建文件、目录；选中目录时在其内部创建，选中文件时在同级创建。
- 支持复制、粘贴及文件和目录拖入；拖放按复制处理，同名项可保留副本或跳过。
- 使用 `Ctrl`、`Shift` 多选后批量复制、拖动或删除。删除移入系统回收站，需要确认。
- 图片提供只读预览、缩放、原始尺寸和适应窗口，支持 PNG、JPEG、GIF、WebP、BMP、ICO、AVIF、SVG。

### 日常 Git 操作

![Git 工作区：变更列表、状态颜色与文本差异](docs/images/git-changes.png)

在顶栏点击分支名，搜索并切换本地分支；在 Git 工作区查看修改、选择文件暂存、填写提交说明，再推送到远端。提交历史可以分页查看。

文件树和 Git 列表使用相同的状态颜色：

| 颜色 | 状态 |
| --- | --- |
| 红色 | 未跟踪的新文件；冲突文件另有冲突标记 |
| 绿色 | 已暂存且没有后续工作区修改 |
| 蓝色 | 已跟踪文件存在未暂存修改，包括暂存后继续修改 |
| 灰色 | 已删除的文件 |
| 常规文字颜色 | 没有修改 |

“拉取”采用仅快进策略；本地和远端分叉时，使用“合并远端”获取并合并上游提交。Git 复用系统凭据，不会自动强制推送或丢弃本地修改。

## 处理合并冲突

![独立三栏合并窗口：本地版本、合并结果和待合入版本](docs/images/conflict-merge.png)

合并出现冲突时，Git 工作区会列出冲突文件。点击文件或“打开三栏合并”，在独立弹窗中处理：

1. **左侧查看本地版本，右侧查看待合入版本，中间编辑最终结果。** 冲突导航可跳转到待处理位置。
2. 点击 `>>` / `<<`，把对应一侧的改动采用到中间；点击 `×` 拒绝这一侧的改动，保留当前中间结果。也可以使用底部“采用左侧”“采用右侧”“两边都保留”。
3. 三栏支持横向、纵向同步滚动。点错合并操作时，使用 `Ctrl+Z` 撤销，`Ctrl+Y` 或 `Ctrl+Shift+Z` 重做。
4. 冲突全部处理后，点击“应用更改”，保存并暂存该文件。
5. 所有冲突文件处理完成后，回到 Git 工作区提交合并，再推送。

推送因远端新提交被拒绝时，也按“合并远端 → 处理冲突 → 提交合并 → 推送”的顺序处理。需要放弃整次合并时，可使用“中止合并”。

## 快速开始

### 环境要求

- **Windows**：当前主要面向的平台；其他系统尚未提供同等验证。
- **Node.js 与 npm**：建议使用 Node.js 22.12 或更高版本，满足当前 Vite 依赖的运行要求。
- **Git**：已加入系统 PATH；访问远端时使用本机已配置的凭据或 SSH 密钥。
- **目标项目所需的运行环境**：如 Python / uv、Java。工作台复用这些环境，不负责安装。

### 从源码启动

```powershell
git clone https://github.com/lyunsheng051-png/ai-project-manager.git
cd ai-project-manager
npm ci
npm run dev:desktop
```

首次安装需要联网下载 Electron 运行时。依赖安装完成后，也可以双击项目根目录的 `start.cmd`。

启动后会打开独立桌面窗口。开发版内部启动本机界面服务并自动选择空闲端口，关闭客户端后服务一并退出。

### 第一次使用

1. 导入已有项目目录，或克隆一个 Git 仓库。
2. 在“运行服务”核对扫描得到的目录和命令，补充环境变量及依赖关系。
3. 打开项目终端，安装目标项目依赖。
4. 启动服务，在下方面板查看日志；需要时打开多个终端。
5. 在“文件浏览”编辑文件，在“Git 变更”检查、暂存和提交修改。

Windows 服务命令和终端默认使用 `cmd.exe`。需要 PowerShell 时，可在终端中执行 `powershell -NoProfile`。

| 操作 | 快捷键或入口 |
| --- | --- |
| 保存当前文本文件 | `Ctrl+S` |

## 开发与贡献

项目使用 Electron + Vue 3 + Vite + TypeScript。代码编辑基于 CodeMirror 6，终端使用 xterm.js + node-pty，Git 操作调用系统 Git CLI。

### 开发命令

| 命令 | 用途 |
| --- | --- |
| `npm run dev:desktop` | 启动桌面开发环境 |
| `npm run desktop` / `npm run dev` | 桌面启动的兼容入口 |
| `npm run dev:web` | 浏览器界面预览，不包含桌面文件、Git 和 PTY 能力 |
| `npm run typecheck` | 检查 Vue、共享类型和 Electron 主进程类型 |
| `npm test` | 核心逻辑测试，使用独立临时项目 |
| `npm run test:desktop` | 桌面自动化场景 |
| `npm run test:desktop:launch` | 桌面启动入口检查 |

Vue 界面修改支持热更新；修改 `electron/` 或 `shared/` 后需要重启客户端。桌面启动只转换主进程代码，界面由 Vite 开发服务器提供，无需执行前端生产构建。

### 目录结构

```text
electron/
  core/                 路径约束、任务队列等基础能力
  repositories/         本地项目配置与外观设置存储
  services/             项目扫描、文件、Git、服务进程与 PTY
  main.ts               桌面生命周期与 IPC 接口
  preload.cjs           隔离的桌面桥接
shared/                 桌面与渲染端共享契约
resources/              Logo 原图、Windows 图标及各尺寸 PNG
src/
  api/                  桌面接口调用
  components/           项目、服务、Git、文件与终端组件
  composables/          工作空间、编辑标签、选区与布局逻辑
  config/               展示映射与静态配置
  layouts/              应用框架
  router/               页面路由
  styles/               主题、设计变量与组件样式
  types/                前端类型入口
  views/                工作台与设置页面
scripts/                启动与自动化脚本
tests/                  核心行为测试
docs/                   架构说明与项目截图
```

实现细节见 [架构说明](docs/architecture.md)；已有测试场景记录见 [验证记录](docs/verification.md)，其中的历史结果不代表后续所有改动均已验证。

## 数据与当前边界

- 项目配置保存在 Electron `userData` 下的 `projects.json`；服务环境变量目前以明文存储在本机，请妥善管理。外观配置也保存在本机。
- 移除项目记录不会删除磁盘项目；文件删除调用系统回收站，失败时不降级为永久删除。
- 文本编辑支持不超过 1 MB 的 UTF-8 文件，保留原有 BOM 和换行格式；保存前检查外部修改。图片只读，预览上限为 20 MB。
- 文件复制不覆盖、合并已有同名目录；符号链接和 Git 内部项受到限制。当前不提供文件重命名、完整语言服务或断点调试。
- 日志与终端输出使用有界缓冲，不保证跨重启保留完整历史。强制结束应用后的进程恢复不在当前范围内。
- Git 支持文本冲突的图形合并；二进制文件、复杂重命名冲突等情况建议使用系统 Git 或外部工具。当前不提供 rebase、强制推送或内置 Git 托管账号登录。
- 应用工作集统计是 Electron 各进程的合计，可能重复计算共享页，不包含用户项目服务；不承诺固定内存指标。

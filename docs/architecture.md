# 桌面第一版架构

## 职责边界

Vue渲染端负责展示和交互，不能直接访问Node。sandbox和contextIsolation保持开启；preload只暴露固定请求入口和事件订阅。主进程校验请求来源、操作名称及参数后调用本地服务。

`dev:desktop` 启动器转换主进程并启动随机本机端口的 Vite 服务，然后打开 Electron；不会打开系统浏览器。正常启动清除隐藏测试标志，界面加载后主动显示和聚焦窗口。桌面进程通过父子 IPC 报告窗口就绪；退出及 Ctrl+C 沿用主进程清理流程。网页预览独立使用固定的 5178 端口。

项目存储采用应用数据目录中的JSON快照，通过串行写入及临时文件重命名保存。配置损坏时保留原文件副本并报错。扫描器有深度和目录数量上限，忽略依赖和产物目录，不跟随目录链接。

Git使用系统CLI与参数数组调用，写操作按仓库串行。工作区状态使用NUL分隔输出，避免空格和中文路径解析错误。外部程序并发操作Git时仍可能出现锁或状态冲突，此时展示Git返回的错误并允许刷新，不强行解锁。

服务和终端使用node-pty。服务保留有界输出并向界面批量发送；终端由xterm.js渲染。Windows停止流程先对登记的PTY进程运行taskkill进程树清理，再关闭PTY并等待退出事件。运行中的进程不等同于就绪服务；填写HTTP地址后单独探测。

## 启动状态

无就绪地址：启动 -> 运行中 -> 已停止/失败。

有就绪地址：启动中 -> HTTP响应 -> 已就绪。45秒内未确认则显示运行中及提示；进程退出则显示退出码。组合启动遵循配置依赖，前一服务未就绪时停止后续启动；已启动的服务保留并可统一停止。

取消组合启动、停止服务和退出应用会使未完成的启动令牌失效，避免等待路径/端口检查后继续创建新进程。服务删除前检查其他配置是否依赖它。

## 工作区布局

项目上下文使用 44px 顶栏，功能导航为 35px。Git 文件列表和差异预览各自滚动，提交说明与提交按钮固定在文件列表底部，提交历史保留分页。文件浏览左侧为不分页的目录树，根节点默认展开，子目录按需加载，保留展开状态并支持全部收起、键盘导航、失败重试和刷新；右侧保留文本预览与编辑。目录树刷新不覆盖编辑中的草稿。

Git 和文件页面至少保留 260px 的工作区域。切换页面时重新计算输出面板上限，避免在服务页拖大终端后遮住 Git 的文件和提交区域。输出面板默认高度为 220px，小窗口为 180px；已有手动设置会保留，并根据当前可用空间限制实际高度。

文件编辑通过 `files:save` 白名单接口进入主进程，重新检查项目路径边界与 UTF-8 内容。按文件串行保存，比较读取时的原内容，并通过同目录临时文件重命名替换，保留 BOM 和换行格式。发现外部修改时拒绝覆盖。未保存内容在切换文件、功能页、项目或设置页前提示；刷新和关闭时通过卸载拦截提示。无法对其他进程的写入实施跨进程文件锁，应避免多个工具同时保存同一文件。

文件树和 Git 变更列表共用状态颜色：未跟踪红色、仅暂存绿色、工作区修改蓝色、冲突红色，无变化维持常规字体颜色；目录汇总子项状态，选择文件时保留状态颜色。文本文件默认进入 CodeMirror 编辑器，语法按文件类型异步载入，输入时实时更新高亮，不渲染或执行源 HTML。行号与编辑区域按可见范围渲染，保留深色代码主题。

`useFileTabs` 管理每个打开文件的原文、草稿、加载与保存状态，`FilePanel` 提供可关闭标签。同一项目在文件页、服务页和 Git 页之间切换时保留文件面板；各文件的编辑器保持独立实例，以保留撤销历史、光标和滚动位置。切换标签不保存、不清空草稿，只有 Ctrl+S 调用保存接口。关闭脏标签需要确认，切换项目或退出统一检查所有未保存文件，图片标签始终只读。

图片通过 `files:image` 读取项目内文件，检查格式、路径边界和 20 MB 大小上限，返回有明确 MIME 的 data URL，由图片元素解码。SVG 以图片模式显示，不以内联 HTML/对象方式执行。主进程的文本保存接口同样拒绝图片（包含 SVG），保证图片只读。

## 第一版限制

- 需要开发服务器，尚未提供安装包。
- Windows优先；其他平台相关分支未经同等桌面验证。
- 不提供完整IDE、语言服务、断点调试、代码补全或AI编码代理。
- 文件浏览提供轻量纯文本编辑，Markdown也以源文展示，不执行仓库HTML/脚本。只编辑已有的 UTF-8 文件，大小上限 1 MB；不支持新建、删除或重命名文件。
- 只发现常见入口，描述文件、环境管理器和复杂工作区仍需用户核对。
- 配置文件存储尚未加入操作系统密钥库，环境变量按明文处理。
- 不支持应用被强制结束后的跨重启进程恢复，也不自动接管外部服务。

## 后续AI扩展

优先把项目运行与Git功能做好。未来LangGraph模块只在需要时启动，基于选定描述文件及日志产生建议，通过人工确认后交给本地执行层。基础功能无需模型调用或Python常驻服务。
